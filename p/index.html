برومبت واحد = لعبة جوال كاملة

غيّر [فكرة اللعبة] بس، واحفظ الناتج باسم game.html وافتحه من جوالك.

You are a professional mobile game developer. Make me a complete, ready-to-play mobile game in a single HTML file.

Game idea: [your game idea]

Requirements (all of them):
1) One file only with HTML, CSS and JavaScript. No external library, image, file or font. Draw all graphics in code on a <canvas> (shapes and gradients), and don't use emoji as characters.
2) Portrait mobile: the canvas fills the screen and adapts to any size, to the screen density (devicePixelRatio) and to window resizing. Add:
   <meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no">
   and block dragging, zooming and selection (touch-action:none; user-select:none; overflow:hidden).
3) Touch controls: a single tap, or tapping the right/left half of the screen if the idea needs two directions. Use pointerdown on the whole screen with preventDefault, and the tap responds instantly. It also works with the mouse, and with Space and the arrow keys on a computer.
4) Three clear screens:
   - Start: game name + how to play in one line + a big "Start" button.
   - Play.
   - Game over: score + best score + a "Play again" button (enabled after 0.6 s so it isn't pressed by mistake) that resets everything without reloading the page.
5) Score: shown at the top during play, with a small pop animation when it goes up. Save the best score in localStorage inside try/catch (if storage is blocked, keep it in a variable without throwing an error), and show "New record!" when it is beaten.
6) Fair difficulty: the first 5 seconds are very easy, then it speeds up gradually to a reasonable cap. Every obstacle must always be avoidable, and check it by time, not by eye: the time between two consecutive obstacles reaching the player (at the real relative speed, counting obstacle length and player size) must be longer than the dodge move takes + 0.3 s. If the game has lanes: every row leaves one lane open, and the new open lane is close to the previous one. If obstacles move at different speeds, make sure they never catch up with each other and block the whole path. The hitbox is about 20% smaller than the drawing.
7) Same speed on every device: requestAnimationFrame with frame delta in seconds capped at 0.05, and all speeds in pixels per second, not per frame. Pause the game when the user leaves the page (visibilitychange).
8) Style: near-black dark background, the hero, score and buttons in gold #f3c766 with a light neon glow (shadowBlur), and a layered parallax background that draws the idea's setting. All in-game text is in Arabic, right-to-left, in the system font (system-ui, Tahoma, sans-serif), and buttons are finger-sized (60px tall or more). Titles and numbers shrink automatically (clamp with vw) so nothing goes off screen even on a 360px-wide phone, and obstacles are clear and contrast with the background (no dark on dark).
9) Game feel: a light screen shake on losing, small particles on jumping or scoring, and simple sounds generated with Web Audio that start after the first tap, with a small mute button in the corner.
10) No bugs: define every variable before using it, and review the code yourself before sending it: start -> play -> lose -> play again, and make sure there are no console errors.

What I need from you:
- Write the full code in one block, with no shortcuts, no "..." and no "continue here". If you can, show it as an Artifact so I can try it right away.
- After the code, only two lines: how to play, and how to run it on my phone (save the file as game.html and open it in the browser).

كود Hit-stop — ليش ضربة إلدن رنق تحسّ فيها

Unreal Engine 5 — C++

Here is the complete Hit-stop code (Unreal Engine 5 - C++):

// ===== Hero.h (inside class AHero) =====
UPROPERTY() TObjectPtr<AActor> HitVictim;
FTimerHandle H;
void StartHitStop(AActor* Victim, float Seconds = 0.08f);
void EndHitStop();

// ===== Hero.cpp =====
void AHero::StartHitStop(AActor* Victim, float Seconds)
{
    HitVictim = Victim;
    CustomTimeDilation = 0.05f;                              // the attacker (this) nearly frozen
    if (HitVictim) HitVictim->CustomTimeDilation = 0.05f;    // and the enemy too
    // the world timer ignores the actor's CustomTimeDilation, so 0.08 = a real 80ms
    GetWorldTimerManager().SetTimer(H, this, &AHero::EndHitStop, Seconds, false);
}

void AHero::EndHitStop()
{
    CustomTimeDilation = 1.f;
    if (HitVictim) HitVictim->CustomTimeDilation = 1.f;
    HitVictim = nullptr;
}

How to use it:
1) Call StartHitStop(TheEnemy) the moment the hit lands (from an AnimNotify or right after applying damage).
2) Light hits 0.05–0.08, heavy hits 0.12–0.15. To freeze the whole world use UGameplayStatics::SetGlobalTimeDilation, but note the timer then runs in slowed time.

كود «العدو شافك؟»

Unreal Engine 5 — C++

Here is the complete "Can the enemy see you?" code (Unreal Engine 5 - C++):

// ===== EnemyCharacter.h (inside class AEnemyCharacter) =====
UPROPERTY(EditAnywhere) float SightRange = 1500.f;     // max sight distance (cm)
UPROPERTY(EditAnywhere) float HalfAngleDeg = 35.f;     // half of the cone angle
bool CanSee(const AActor* Player) const;

// ===== EnemyCharacter.cpp =====
bool AEnemyCharacter::CanSee(const AActor* Player) const
{
    if (!Player) return false;

    FVector Eye; FRotator EyeRot;
    GetActorEyesViewPoint(Eye, EyeRot);                 // eye position and direction
    const FVector Forward   = EyeRot.Vector();
    const FVector PlayerLoc = Player->GetActorLocation();
    const FVector ToPlayer  = PlayerLoc - Eye;

    // 0) too far?
    if (ToPlayer.SizeSquared() > FMath::Square(SightRange)) return false;

    // 1) inside the cone?
    const float CosHalfAngle = FMath::Cos(FMath::DegreesToRadians(HalfAngleDeg));
    const float Dot = FVector::DotProduct(Forward, ToPlayer.GetSafeNormal());
    if (Dot < CosHalfAngle) return false;

    // 2) a wall in between?
    FCollisionQueryParams Params(SCENE_QUERY_STAT(EnemySight), false, this); // ignore the enemy itself
    FHitResult Hit;
    GetWorld()->LineTraceSingleByChannel(Hit, Eye, PlayerLoc, ECC_Visibility, Params);
    return !Hit.bBlockingHit || Hit.GetActor() == Player;
}

How to use it:
1) Call CanSee(Player) every 0.1–0.2 s on a timer (not every frame) for performance.
2) If it returns true: the enemy notices (a "!" marker) and starts chasing.
3) Trick: trace to the player's head and to their middle; if either is clear = seen (the player doesn't vanish just because their legs are behind a box).
4) Ready-made option: UAIPerceptionComponent + UAISenseConfig_Sight does the same thing internally.
